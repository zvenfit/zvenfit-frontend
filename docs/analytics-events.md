# События сайта и переключение GTM

## Контракт

Все пользовательские события проходят через `window.__ZVENFIT_ANALYTICS.track(event, parameters)`
из `src/scripts/analytics.js`. Модуль не вызывает Метрику, VK или другие пиксели напрямую:
он кладёт событие в существующую `window.dataLayer`, а опубликованные теги GTM определяют получателей.
Просмотры страниц и инициализация действующих счётчиков остаются в прежней схеме.

| Событие | Параметры | Точный смысл |
|---|---|---|
| `form_submit_attempt` | `form_type: lead / newsletter` | Активация кнопки отправки до валидации, включая Enter |
| `form_submitted` | `form_type: lead / newsletter` | API подтвердил сохранение обращения: HTTP 2xx, `ok === true`, непустой ID |
| `lead_form_click` | `form_type: lead` | Активация ссылки на страницу формы своего сайта |
| `contact_click` | `contact_method: phone / email / telegram / whatsapp / max / vk` | Активация контактной ссылки; не состоявшийся звонок или диалог |
| `map_open` | `map_provider: yandex / google / 2gis` | Активация ссылки на карты; не показ карты на странице |
| `app_download_click` | `app_platform: app_store / rustore / android_apk` | Переход к приложению ZvenFit; не подтверждённая установка |
| `schedule_loaded` | — | Расписание успешно загружено и отрисовано, включая пустой корректный ответ |
| `schedule_event_open` | — | Открыты подробности занятия; не подтверждённая запись |
| `engagement_30s` | — | 30 секунд после готовности DOM, один раз за документ, включая время фоновой вкладки |
| `scroll_depth` | `scroll_percent: 50` | Нижняя граница viewport достигла 50% высоты документа, один раз за документ |

`newsletter` применяется только к рассылке Эстетики, события расписания — только к основному сайту.
Подтверждения покупки, записи на занятие и установки приложения в текущем фронтенде нет:
такие конверсии потребуют результата соответствующего сервиса, а не переименования клика.

Обработчик допускает только строковые имена из справочника и перечисленные значения параметров.
Посторонние параметры отбрасываются, неизвестные события/значения отвергаются.
Имя, телефон, email, Telegram, ID заявки, текст ссылки, полный URL, query/UTM,
названия занятий и произвольные свойства в события не передаются.
Параметры GTM следует читать только в триггере соответствующего события: data layer version 2
сохраняет последние значения параметров между событиями.

Формы сохраняют опубликованный контракт и защиту от повторной отправки. Ошибки API,
антиспам-ответ без ID и фоновые сетевые повторы не создают успешные конверсии.
Подробности: [события форм](form-analytics.md).

## Покрытие и доставка

Ссылки распознаются общим capture-обработчиком по стандартным протоколам, точным hostname
и маршрутам назначения. Тексты кнопок, CSS-классы и видимость блоков не являются контрактом.
Это охватывает вложенные элементы ссылок, клавиатурный click, среднюю кнопку мыши
и ссылки, добавленные картой или расписанием после загрузки страницы.
Неизвестные домены, заглушки `#`, `aria-disabled=true` и элементы внутри
`[data-analytics-ignore]` пропускаются. Новый способ контакта/магазин добавляется
в классификатор и тесты; обычная смена оформления не требует перенастройки GTM.

Для обычного HTTP(S)-перехода в той же вкладке при запущенном загрузчике GTM обработчик
передаёт служебные `eventCallback` и `eventTimeout: 800`, ждёт обработки тегов
не более 800 мс и продолжает переход ровно один раз. Собственный fallback работает
при блокировке GTM, отсутствии callback или исключении тега.
Телефон/email, Ctrl/⌘/Shift/Alt-клик, новая вкладка, скачивание и страницы без загрузчика GTM
сохраняют нативную навигацию. Callback подтверждает обработку GTM, не запись
в кабинете аналитики; для тегов требуется совместимый с уходом со страницы транспорт.
Событие не сохраняется в cookies/storage и не пересылается повторно на следующей странице.

## Подключение и кэш

Base.astro подключает один `defer is:inline`-скрипт из `src/scripts/analytics.js?url`
в head. URL имеет хеш содержимого `/_astro/analytics.<hash>.js`. Legacy-копия
в `public/js` остаётся для сравнения и использует `ASSET_VERSION`.
Существующий порядок выкладки ассетов и HTML сохраняется.
Astro development/staging отключают production-теги. Legacy development сохраняет
GTM и счётчики: для проверки legacy использовать staging или блокировать внешние теги.
Повторное подключение модуля не создаёт вторых listeners или engagement-таймеров.

Одинаковая реализация и runtime-тесты хранятся в обоих репозиториях: отдельный пакет
и зависимость публикации одного сайта от другого не вводятся. При изменении
общего контракта обновлять обе копии и проверять их побайтное совпадение.

## Проверка

```sh
node --test scripts/__tests__/analytics.test.cjs scripts/__tests__/form-analytics.test.cjs
npm run test:build
```

Runtime-тесты проверяют схемы, отсутствие произвольных данных, типы ссылок,
игнорируемые действия, клики/модификаторы, callback и timeout перехода, ошибки тегов,
повторную инициализацию, таймер/scroll и сценарии форм. Build-контракт проверяет
покрытие страниц, исключения, один versioned/defer loader и его порядок в head.

## Порядок переключения

1. Экспортировать актуальный контейнер GTM и записать его версию для отката.
   Опубликованный JS позволяет инвентаризировать активные теги, но не заменяет
   export: черновики, имена объектов и отключённые конфигурации надо сверить в кабинете.
2. Создать переменные уровня данных version 2: `form_type`, `contact_method`,
   `map_provider`, `app_platform`, `scroll_percent` — по используемым тегам.
3. Создать Custom Event triggers с точными именами из таблицы и нужными фильтрами.
   Для попытки формы использовать отдельную цель, не цель успешной заявки.
4. В существующих тегах заменить firing triggers по таблице ниже. Не копировать
   тег конверсии и не оставлять одновременно старый и новый триггер той же цели.
   Существующие ID счётчиков и названия целей сохраняются.
5. Сначала развернуть и проверить новый frontend; текущие production-теги пока
   продолжают работать по прежним триггерам. Затем проверить draft контейнера
   через Preview: клик/Enter, невалидная форма, 202, ошибка, повтор, телефон,
   карта, отзыв согласия, таймер/scroll. В Tag Assistant — один запуск ожидаемого
   тега, без запуска старого триггера на то же действие.
6. Опубликовать согласованный контейнер. Проверить получение целей в кабинетах;
   присутствие в `dataLayer` само по себе не доказывает доставку в Метрику/VK.
7. При откате GTM восстановить сохранённую версию контейнера. При откате frontend
   согласовать обратное переключение тегов: старый код не генерирует новые события.

Публикация GTM ожидает согласования с маркетологом; эта инструкция и код не означают,
что контейнер уже переключён. Новые события без существующих целей сначала видны
в Preview; привязка к дополнительным целям и системам согласуется отдельно.

## Инвентаризация ZvenFit

Снимок опубликованного `GTM-5532ZMV5` от 10 ноября 2026 года:
`resource.version=12`, 7 активных тегов целей; два тега инициализации на паузе.
Счётчики: Метрика `107738850`, VK/Top.Mail.Ru `3750316`.
Названия объектов workspace по опубликованному JS недоступны, ниже указаны tag_id.

| tag_id | Получатель / существующая цель | Старое условие | Новое событие и фильтр |
|---|---|---|---|
| 7 | Метрика: `30 sec` | GTM timer 30 секунд | `engagement_30s` |
| 10 | VK: `30_sec` | GTM timer 30 секунд | `engagement_30s` |
| 9 | Метрика: `knopka_ostavit_zayavku` | Текст содержит «ОСТАВИТЬ ЗАЯВКУ» | `lead_form_click`, `form_type=lead` |
| 11 | VK: `form_submitted` | `gtm.formSubmit` | `form_submitted`, `form_type=lead` |
| 19 | Метрика: `form_submitted` | `gtm.formSubmit` | `form_submitted`, `form_type=lead` |
| 15 | Метрика: `knopka_pozvonit_nam` | Текст «ПОЗВОНИТЬ НАМ» или основной телефон | `contact_click`, `contact_method=phone` |
| 16 | Метрика: `knopka_pokazat_na_karte` | Текст «ПОКАЗАТЬ НА КАРТЕ» | `map_open` |

После перехода на семантику ссылок будут охвачены и другие тексты кнопок,
второй телефон, динамические контакты и все поддерживаемые карты: это расширяет
покрытие прежних целей, поэтому дату переключения нужно отметить в отчётах.

Loader и 30-секундное событие — на всех 40 обычных страницах; 404 исключена.
Прокрутка на основном сайте сейчас не включается: действующей цели scroll здесь нет.
Для новых контактов, приложения и расписания действующих тегов в снимке не найдено.
Их события доступны для последующей настройки целей.
