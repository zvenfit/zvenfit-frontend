## MAX как второй канал уведомлений о заявках

Добавлено 2026-09-27.

Сейчас менеджеры узнают о заявках только из Telegram. Доступ к
`api.telegram.org` из Yandex Cloud уже нестабилен: в
[`telegram/routes.ts`](../../functions/lead-intake/src/telegram/routes.ts)
есть проба маршрутов и резервные IPv4 из `TELEGRAM_API_FALLBACK_IPV4S`. Если
Telegram станет недоступен, заявки сохранятся в YDB, но до менеджеров не дойдут.
Алерты мониторинга тоже идут в Telegram, но дублируются на email.

Идея: добавить MAX вторым адаптером уведомлений рядом с Telegram. Точка
расширения уже есть: `notificationSender` подключается в composition root.

Не путать с вариантом «Написать в Макс» в форме заявки: это способ связи
с клиентом, а не канал уведомления менеджеров.

Открытые вопросы:

- слать в оба канала всегда или переключаться на MAX только при сбое Telegram;
- как хранить статус доставки по каждому каналу: схема YDB сейчас содержит
  только поля `telegram_*`;
- есть ли у MAX API для ботов организаций, на каких условиях и доступен ли он
  из Yandex Cloud;
- сравнить с другими вариантами: email, SMS, запись заявки сразу в CRM Fitbase
  (см. [`fitbase-integration-plan.md`](fitbase-integration-plan.md)).
